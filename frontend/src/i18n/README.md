# Локализация интерфейса

Интерфейс говорит на русском и английском. Язык выбирается в шапке, по умолчанию —
русский; выбор хранится в `localStorage` под ключом `barbersearch.locale`.

## Как устроено

- `src/i18n/locale.ts` — список языков, `localStorage` и тег `Intl`.
- `src/i18n/translate.ts` — `t()`, `tp()`, `translate()`. Ключ — **русский исходный
  текст**, значение — перевод. Это gettext-подход: непереведённая строка остаётся
  русской, а не превращается в ключ.
- `src/i18n/plurals.ts` — формы счётчиков (`1 отзыв`, `2 отзыва`, `5 отзывов`).
- `src/i18n/messages/en/*.json` — английский каталог по областям. Одинаковый
  русский ключ должен переводиться одинаково во всех файлах.
- `src/i18n/i18n-provider.tsx` — провайдер и `useI18n()`. `App` подписан на
  контекст, поэтому смена языка перерисовывает всё дерево; библиотекам достаточно
  импортировать `t`.

## Правила перевода

- В `t()` попадает **весь видимый текст**: JSX-текст, `aria-label`, `title`,
  `placeholder`, `alt`, тексты ошибок и пустых состояний. Комментарии остаются
  русскими, API-значения, CSS-классы, URL и `data-*` не переводятся.
- Динамические строки: `t('Салон: {name}', { name })`. В каталоге плейсхолдер
  сохраняется дословно.
- Счётчики — только через `tp()`/`format*Count()`, не через конкатенацию числа и
  русского слова.
- Самоназвания языков (`Русский`, `English`, `Deutsch`…) не переводятся.
- Английский текст — обычный регистр предложения, без точки в кнопках и коротких
  подписях; тон нейтральный, как в русской версии. Время 24-часовое, даты в
  порядке «день-месяц» (`en-GB`), валюта — рубль (`RUB`).
- `BarberSearch`, названия салонов, услуг и городов из API не переводятся.
- Нативная подсказка `input[type=date]` зависит от локали браузера, а не от `lang`
  страницы. Пустое поле даты поэтому показывает локализованную подсказку через
  `ui/input.tsx`; не добавляйте сырой `input type="date"` в обход компонента. Календарь
  и выбор времени, которые рисует сам браузер, остаются на языке браузера.

## Проверка

```bash
npm run check:i18n          # отчёт
npm run check:i18n -- --strict  # падает на видимом русском вне t()
```

Скрипт проверяет, что у каждого `t('…')` есть английский перевод, что в JSON нет
конфликтующих ключей и что в JSX-тексте и статических атрибутах не осталось русского
без `t()` (с явным списком исключений для парсеров и самоназваний). Литералы внутри
констант-словарей считаются предупреждением: их переводят через `t(CONST)` на месте
